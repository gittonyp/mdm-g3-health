# Status and Roadmap

Snapshot: 2026-10-22. This page separates what is working, what is partial, and what remains, with acceptance criteria.

## Completed

- ESP32 firmware for HR, SpO2, HRV, activity, fall detection, local alerts, OLED, and recalibration.
- MQTT contract for `vitals`, `motion`, `event`, `status`, and `cmd`.
- Simulator with `normal`, `stress`, `fall`, `no_finger`, and `offline` scenarios.
- Single-container FastAPI server: MQTT ingestor, SQLite, REST API, CSV export, live dashboard, history page.
- Rule-based anomaly detection with watch/alert levels.
- Colab/Kaggle training notebook on the Non-EEG dataset with LOSO evaluation.
- Exported artifacts: personal logistic regression, global models, robust z, Mahalanobis, TFLite MLP.
- Server-side personalized inference with per-device 30-second windows and 120-second calibration.
- Verified live scoring: calibration completes and stress data produces `alert` from the model.
- Unit tests for feature extraction, model scoring, artifact loading, and buffer behavior (5 passing).
- Docker image and Render Blueprint.
- Public GitHub repository and this documentation set.

## Remaining work

### 1. Firmware temperature (high) - implemented, awaiting hardware validation

`health_node/health_node.ino` now reads the LM35 and publishes `temp` (see `hardware.md`). It is compile-tested; the acceptance criteria below still need a run on the real board.

Original scope:

Scope:

- Wire the LM35 to `D33` (ADC1) with a 0.1 uF decoupling capacitor.
- Convert ADC to Celsius and smooth it.
- Add `temp` to the vitals JSON payload.
- Verify the dashboard stops simulating and the server stores the value.

Acceptance criteria:

- `GET /api/vitals` shows plausible `temp` values for the real device.
- Dashboard temperature matches the sensor within the calibration tolerance.
- Temperature rule anomalies (watch/alert) fire as expected.

### 2. On-device inference (high)

Move inference from the server to the ESP32, or at least demonstrate it there.

Recommended path:

- Start with the logistic regression artifact (15 coefficients, intercept, per-device median/MAD) because it is tiny and explainable.
- Optionally add the 4,940-byte TFLite MLP via TensorFlow Lite Micro as the "Tiny ML" demonstration.
- Maintain 30-second buffers and port the 15-feature extractor with exact parity.
- Publish anomaly results with `source: "edge"` and decide how the server avoids duplicate alerts.
- Keep server inference as a fallback.

Acceptance criteria:

- Feature parity test: the same input sequence produces the same 15 features on device and in Python within a defined tolerance.
- On-device calibration from 120 seconds of normal data.
- Published edge anomaly matches the server model on replayed data.
- Measured and documented: inference time, feature-extraction time, free heap, flash size, model size.
- Firmware and docs updated; dashboard unchanged (same contract).

### 3. Research experiments (high)

### 4. Dashboard anomaly detail (medium)

The live dashboard currently only raises the banner on `alert`; it ignores `watch` and does not display the score, source, or reason.

Scope:

- Display anomaly level, score, source (`rule`/`model`), and reason.
- Show model calibration state (`watch` only after calibration, or a "calibrating" indicator).
- Optionally show a short anomaly history or trend.

Acceptance criteria:

- A model anomaly is visible on the dashboard, not only in `/history`.
- Calibration state is visible to the operator.
- No regression in the existing vitals/motion/fall views.

### 5. Render deployment verification (medium)

- Sign in to Render and deploy the Blueprint.
- Confirm `/api/health`, `/api/model`, dashboard, and `/history` work on the public URL.
- Confirm MQTT ingestion from a simulator and from the ESP32.
- Document the deployed URL and any differences from local.

Acceptance criteria:

- End-to-end data reaches the deployed server from the public broker.
- Known limitations (single port, ephemeral DB, sleep) are confirmed and documented.

### 6. Persistence (low, demo decision)

Free Render uses `/tmp`, so history is lost on restart. Options: paid disk, Render Postgres, Turso, or accept the limitation for the demo.

### 7. Hardware-in-the-loop validation (medium)

Run the full system with the real board:

- Record a normal session and a stress/activity session.
- Replay through the server model.
- Compare rule, server model, and (after step 2) edge model.
- Record video/screenshots for the demo.

## Explicit non-goals

These were descoped by project decision and should not be added without a new agreement:

- Authentication, authorization, TLS enforcement, or per-device identity.
- Automated end-to-end test suite (one-off headed Playwright checks only).
- Installing TensorFlow/PyTorch on the local machine; training stays in Colab/Kaggle.
- Self-hosted Mosquitto; HiveMQ is the broker.
- Multi-container deployment (Caddy, Postgres, workers). The demo stays in one container.
- Production clinical use.

## WiFi credentials decision

The firmware keeps WiFi credentials directly in `health_node/health_node.ino`, as requested. This is documented as a demo-only pattern. Do not reuse it for production or for a repository that should not expose those values.
